# Astro

Astro is a Chromium fork by [Oxy](https://oxy.so) that strips every Google service from the browser and replaces it with privacy-respecting Oxy equivalents — auth, sync, AI, search, and update infrastructure. It is the upstream codebase used by every Oxy distribution channel (Linux, Android, macOS, Windows).

## What it is

Astro is built on top of [ungoogled-chromium](https://github.com/ungoogled-software/ungoogled-chromium) (112 inherited patches that remove Google service dependencies) plus 65 Astro-specific patches that add Oxy integrations, branding, and a custom URL scheme. All Astro-only C++ code lives in a self-contained overlay at `src/chrome/browser/oxy/`, following the Brave-style approach of keeping custom source separate from upstream Chromium.

The internal pages Astro owns (New Tab, Settings, Alia AI, What's New) are not Polymer like in upstream Chrome — they are standalone Vite + Tailwind v4 apps. Settings is the newest and the least finished: Astro serves the host, but the page has no assets staged yet ([#16](https://github.com/OxyHQ/Astro/issues/16)). The error page was deleted in `c9c4383` and nothing replaced it. All of these are being consolidated into a single Vite + Tailwind + Bloom application in `webui/app/`.

| Aspect | Astro |
|--------|-------|
| Base | Chromium 146.0.7680.177 (current target) |
| De-Google patches | 112 (inherited from ungoogled-chromium) |
| Oxy patches | 65 (`patches/astro/001-069`; 007, 012, 035 and 068 are unused numbers) |
| Custom WebUI pages | 4 registered (NTP, Settings, Alia, What's New); the error page was deleted |
| URL scheme | `astro://` (aliased to `chrome://`) |
| Default search | DuckDuckGo |
| Auth | Oxy session cookie + JWT, no Google Sign-In |
| Ad blocker | In-process Rust engine, no extension |
| Updates | Self-hosted update server in `services/update-server/` |

## What's different from upstream Chromium

The core differences fall into three buckets:

### 1. Everything Google is gone

The 112 ungoogled-chromium patches remove or stub:

- Google account / sync infrastructure
- Google Safe Browsing pings
- Google Update / Omaha
- All hard-coded Google API keys, client IDs, and OAuth secrets
- The promo notifier, hotword detection, contextual search, etc.
- DNS prefetch / preconnect to Google domains
- Field trial config fetches
- Translate UI's Google Translate dependency (provider is stubbed)

The 65 Astro patches finish the substitution by replacing every remaining `chrome://`, "Google account", "Chromium" string, and product-menu entry with Oxy/Astro equivalents.

### 2. Native Oxy integrations

Custom C++ services that live alongside Chrome's existing services, registered through standard Chromium mechanisms (`KeyedService`, `WebUIController`, `NavigationThrottle`, etc.):

| Component | File | Role |
|-----------|------|------|
| `OxyAuthService` | `src/chrome/browser/oxy/oxy_auth_service.*` | Per-profile auth state, token storage via OSCrypt, refresh timer |
| `OxyAuthCallbackHandler` | `oxy_auth_callback_handler.*` | Handles the `astro://auth/callback` URL the auth flow returns to |
| `OxyAuthNavigationThrottle` | `oxy_auth_navigation_throttle.*` | Intercepts `auth.oxy.so` redirects and rewrites them to the callback handler |
| `OxyCookieSigninObserver` | `oxy_cookie_signin_observer.*` | Detects a `fedcm_session` cookie on `*.oxy.so` and completes browser-level sign-in (mirrors Chrome's "sign in to Google = sign in to Chrome") |
| `OxyAuthTokenStore` | `oxy_auth_token_store.*` | OSCrypt-backed encrypted storage for access + refresh tokens |
| `OxyAliaSidePanel` | `oxy_alia_side_panel.*` | Registers the Alia AI panel in Chrome's side-panel registry |
| `AstroAdBlockService` | `adblock/astro_adblock_service.*` | KeyedService that owns the Rust engine, filter list catalog, and updater |
| Astro WebUI pages | `webui/astro_*_ui.*` | `chrome://astro-ntp`, `chrome://settings`, `chrome://alia`, `chrome://whats-new` |
| `AstroThemeService` | `astro_theme_service.*` | Watches the light/dark and Bloom-preset prefs, repaints the native UI, and pushes the theme to every open page |

### 3. Vite-built WebUI pages, not Polymer

Chrome's stock internal pages use Polymer 3 + Lit + chrome:// resources baked into the binary. Astro replaces the pages above with standalone Vite + Tailwind v4 apps in `webui/`. The C++ WebUI controllers serve the pre-built `dist/` by reading it off disk at request time, so the assets are in no `.pak`. The three legacy pages render blank, silently, when the directory was not staged; settings, which is built on the shared `astro_webui_page.cc` base, logs the path it tried and serves a page naming it instead. Removing `DIR_EXE` entirely is [issue #14](https://github.com/OxyHQ/Astro/issues/14); packaging the app is [#16](https://github.com/OxyHQ/Astro/issues/16).

Settings uses Mojo; the others do not. Astro's first two interfaces landed on 2026-08-09: `astro_theme.mojom` (read-only — `GetTheme` plus an `OnThemeChanged` observer, so every page follows the browser's theme live) and `astro_settings.mojom` (`SetThemeMode`, `SetColorPreset`). They are narrow and named on purpose — there is no `SetPref(string, value)`, and the page that carried one was deleted in `c9c4383`. Chromium's own prefs still reach settings through `chrome.settingsPrivate`, which is the only transport carrying a pref's policy state. The New Tab page talks to the browser through a `WebUIMessageHandler` (`chrome.send`); Alia and What's New are static bundles.

## URL scheme

Astro adds an `astro://` URL scheme that is aliased to `chrome://` (patch `011-astro-url-scheme-alias.patch`). Both forms resolve to the same WebUI page:

| Page | Internal host | Displayed as |
|------|---------------|--------------|
| New Tab | `chrome://astro-ntp` | `astro://newtab` |
| Settings | `chrome://settings` | `astro://settings` |
| Alia AI | `chrome://alia` | `astro://alia` |
| What's New | `chrome://whats-new` | `astro://whats-new` |

The alias covers every WebUI host, Chromium's own included, so `astro://settings` and `astro://whats-new` resolve whether or not Astro registers the page behind them. Settings is now Astro's: patch `060` SWAPS upstream's registration rather than adding one, which is the only shape that both inherits the host's `settingsPrivate` grant and avoids the duplicate-origin CHECK. What's New still awaits the same treatment. There is no `astro://error` — that page was deleted in `c9c4383`.

The omnibox, autocomplete, security UI, copy-URL, navigation controller, session restore, web app handling, and protocol handler are all patched to display the `astro://` form (patches `021-030`, `037-043`).

## Quick start

A from-scratch build takes 2-4 hours. The shortest path:

```sh
# 1. Fetch Chromium source (~55 GB, 30-90 min depending on link)
tools/sync-sources.sh

# 2. Sync ungoogled-chromium patches for the current Chromium version
tools/sync-ungoogled.sh

# 3. Prune binaries, then apply all 177 patches in declared series order
tools/apply-patches.sh

# 4. Copy the Astro source overlay into the Chromium tree (allowlisted, never deletes)
tools/sync-overlay.sh

# 5. Build (uses all CPU cores; 1-3 hours)
tools/build.sh

# 6. Install locally
tools/install-local.sh

# 7. Run
astro --no-sandbox
```

For incremental WebUI work you do **not** need to rebuild Chromium — point a dev server at each Vite app and reload:

```sh
cd webui/app        && bun run dev    # http://localhost:5178  (strictPort)
cd webui/ntp        && bun run dev    # Vite default: 5173, or the next free port
cd webui/alia       && bun run dev
cd webui/whats-new  && bun run dev
```

See [Build](./build) for the full workflow, cross-compilation, gotchas, and packaging. See [Architecture](./architecture) for the patch model and overlay layout. See [Oxy integration](./oxy-integration) for the auth, cookie observer, Alia, ad blocker, and update server wiring.
