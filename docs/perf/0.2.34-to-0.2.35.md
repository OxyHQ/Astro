# 0.2.34 → 0.2.35 release gate

0.2.35 is the favicon lookup (a page without its own icon gets its site's: one more favicon render per new tab,
intended; de99cfd9), the quit-path fix (166c567e), Astro's logo in the engine's notification helper and WebUI pages
(71dccbdb), ⇧⌘T per profile, the Settings › Tabs layout picker, the Dock tile repair (a few seconds after launch, off the
main thread; it only acts on a copy in /Applications or ~/Applications, so not in `dist/`), settings sync fixes, uBlock
Origin Lite lists 2026.1006.1931 → 2026.1012.1545, and comment removal across the codebase (token-identical). The engine
is rebuilt from 0.2.34's Chromium (8037@{#1673}) with those patches. Measured on 2026-10-13 from 17:05 to 18:14:
`dist/0.2.35/export/Astro.app` (built from e97a1070, notarized; no `-rc` build, this is the shipped one) against
`dist/0.2.34/export/Astro.app`, interleaved, under the perflab lock, with nothing else of ours running. cpu-cap wasn't
running (its log, `/tmp/cpu-cap-league.log`, ends on 10 October), so nothing could pause the benches. The display stayed
awake throughout. The owner's own copy (/Applications/Astro.app) was open and playing video for much of the gate (it held
its "Video Wake Lock"), and the owner used the Mac during some idle windows (rows below), never with the pointer over a
bench window. Both apps share native API version 8, so both ran the tree's bench bundle.

## js-bench (each app's own bundle, 3 alternating runs)

No row separates against 0.2.35 in time. One count does: opening 20 tabs commits 161–169 → 185–191 times, the site icon
a new tab now shows while it loads and then its own (Favicon renders and Image mounts 20 → 40 over 20 tabs, about one more
commit each; db0fb4a9 raised the ratchet for it). Its time went down, not up (open20.taskMs 471 [470–471] → 450
[445–461], open.medianMs 6.9 [6.7–7.0] → 6.1 [5.8–6.1]). A handful of JS-thread rows separate in 0.2.35's favour:
bundle → first commit 122 [121–131] → 118 [112–118] ms, bundle → first window 165 [162–181] → 156 [153–160] ms, typing's
95th-percentile key 8.2 [7.9–8.7] → 6.5 [6.4–7.5] ms, profileSwipe.taskMs 139 [137–141] → 131 [130–133]. With 3 runs a
side a row separates by chance one time in ten, and the report has about a hundred, so these aren't claimed; the
native-bench rows that time the same moments end to end (launch → window shown 426 → 429 ms, new tab) don't move.
Renders, host updates and store updates are identical everywhere else, and so is the bundle (3844 → 3847 KB of
bytecode).

## Verdict

Same within noise: no row separated in its rerun, and nothing is measurably faster, so the notes get no Faster section.
Memory with 20 tabs is about 10 MB lower in both rounds (1203 → 1193 MB in round 2), under 1 %, too small for a Faster
table.
