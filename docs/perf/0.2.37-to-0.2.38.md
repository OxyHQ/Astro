# 0.2.37 → 0.2.38 release gate

0.2.38 collects nightlies 1 to 8: Chromium 155 (official, ThinLTO, PGO), the full uBlock Origin in place of uBO Lite, the window shown before the interface loads, tab freezing past the five most recent, the 60 Hz main-frame throttle, the passkey Bluetooth fix, the bundle prune and the shortcut work. 0.2.37 is native API 9 and 0.2.38 is 11, so the control ran its own bench bundle (`dist/0.2.37/bench/main.jsbundle`, built from `git archive v0.2.37` with the tree's dependencies cloned in). The candidate is `dist/0.2.38-nightly.8/export/Astro.app` (notarized, built from dc14de6c): 0.2.38 differs from it only in its version and build number. Measured on 2026-10-19, interleaved, display awake, on mains power.

Every user-visible row is the same or better. Three rows are worse, and all three are expected:

- **Memory and idle CPU with 1 tab** (285 → 316 MB, 0.18 → 1.13 %): the full uBlock Origin runs an extension process, 75 MB, and native-bench's fresh profile has it compiling its filter lists through the idle window (0.78 % of the 1.13). uBO Lite had no process. Every other process is the same or smaller (the browser process 119 → 82 MB). Settled, xbench measures Astro at 0.05 % with 1 tab, against Helium's 0.09 %.
- **Launch → JS running** (312 → 429 ms): the window now shows before the interface loads, by design. Launch → window shown and → first page painted are 78 and 61 ms earlier.
- **JS-thread time** (js-bench): bundle → first commit 118 → 133 ms, and on a tab switch listenerMs 6.5 → 9.8 and otherJsMs 63 → 68 ms (12 switches). The ranges separate over three runs each. The tab switch itself shows in 6 ms against 35, and launch → first window is 24 % sooner.
