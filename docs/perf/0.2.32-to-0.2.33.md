# 0.2.32 → 0.2.33 release gate

0.2.33 is the rename (Netnyahoo → Astro) plus the History page, sidebar header, New Tab and offline game changes, and five
fixes the ratchet found in the first 0.2.33 build (3a45cc45, 6474dc2d, 17f6d3c6, bb6e98f1, 9e02f48d). Measured on
2026-10-12: `dist/0.2.33/export/Astro.app` (built from 9e02f48d, notarized) against `dist/0.2.32/export/Netnyahoo.app`,
interleaved, under the perflab lock, nothing else of ours running. cpu-cap wasn't running (nothing could pause the
benches). A system daemon (identityservicesd) held about one core throughout, the same for both apps.

0.2.32's bundle names its native modules and its bench channel in the old names (`NetnyahooApp`, `nn`), so the control
ran its own bench bundle, built from v0.2.32's tree: `dist/0.2.32/bench/main.jsbundle` (`--control-bundle`; the benches
learned to drive a pre-rename control in 41bbded0). The candidate ran the tree's bench bundle.

Overlapping throughout: round 3's separation didn't come back. Rounds 3 and 4 split by the owner's input: with the Mac
quiet, 0.2.33's browser process matched 0.2.32's (1 tab 0.095 against 0.092 %; 20 tabs 0.159–0.163 %, 0.2.32 had no

test-only. Three quiet runs aren't enough to rule out a small real cost; a profile with the owner away would settle it.

## Verdict

Same within noise: no row separated in a second interleaved round, and nothing is measurably faster, so the notes get no
Faster section. Open item: browser-process idle CPU while someone uses the Mac (rounds 1 and 3 up, round 4 not; equal
when the Mac is quiet), most likely the test instances' new window level (ceb84a7f), unconfirmed.
